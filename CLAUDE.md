## Product
Personal cloud drive ("Private Telegram Cloud Drive") — Google-Drive-like file manager whose storage backend is the user's own private Telegram channel. Telegram is an implementation detail; the user sees "My Drive". Not a Telegram client (no chats/contacts).

Spec v1.1 (2026-10-19), local only in the project folder (kept out of git) — read before big decisions:

## Stack

Roadmap: Phase 0 foundation → 1 Telegram core (login, channel, manifest, upload/download, index) → 2 file manager → 3 transfers/backup → 4 security/recovery → 5 polish/packaging → 6 V2 (Web, LAN, Drop Zone, WebDAV).

## Recovery-first rules (no shortcuts here)
V1 is not done until clean-device recovery works.
- Telegram = file content; **Remote Drive Manifest** (versioned, in the channel) = metadata source of truth; SQLite = rebuildable cache/index; local files = optional working copies.
- Own stable file/folder IDs; Telegram message IDs only in `remote_ref` / `file_parts`.
- File safety states: LOCAL_ONLY, UPLOADING, REMOTE_SAFE, VERIFIED, SYNCING, CONFLICT, ERROR. Never show "backed up" before VERIFIED.
- Transfer states: QUEUED → PREPARING → RUNNING → PAUSED / RETRY_WAIT / FAILED / COMPLETED / CANCELLED. Persist in SQLite before network work; progress from confirmed bytes; backoff honoring FLOOD_WAIT, no retry storms.
- Delete = virtual Trash first. Conflicts → CONFLICT, never silent overwrite.
- Optional encryption: AES-256-GCM, versioned format, content key wrapped by user passphrase. Never log/store plaintext secrets or API hash.
- Each of these paths needs a runnable test (delete SQLite → rebuild; restart → queue resumes; wrong passphrase → no access).

## Sync, dialogs, media (added 2026-10-20)
- **Conflicts between PCs**: `data/Merge.kt` 3-way merge (base = `manifest-base-<driveId>.json` in app data, local = DB snapshot, remote = newest manifest). One-sided change wins; both-sided keeps newer + marks file CONFLICT (counts as saved; user resolves via context menu). `saveManifestNow()` always pulls+merges first; runner pulls every 60 s. `sync_state.remoteVersion` (DB v2, Room AutoMigration 1→2) = pinned manifest message id last seen. Known gap: a write landing between our pull and our write (seconds) can be overwritten.
- Old manifests pruned after each write: keep newest `TelegramProvider.KEEP_MANIFESTS` (5) in the data channel; found by walking GetChatHistory (`TelegramAccount.clutter`) — SearchChatMessages missed old ones. Every PinChatMessage leaves a "📌 pinned …" service notice (MessagePinMessage); those are deleted too (they cluttered the user's drive channel: 30 found). `StorageProvider.tidy()` runs on drive open: prunes the data channel and, once per drive (`Prefs["tidy2-<chat>"]`), removes manifests + pin notices from the drive channel.
- QR login: `AuthState.WaitQr(link)` via RequestQrCodeAuthentication; QR drawn with io.nayuki:qrcodegen (whole-pixel cells — fractional ones left seams).
- **`TelegramAccount.call` must use `sendUnsafe`** (2026-10-21): tdlight's `SimpleTelegramClient.send()` holds every function outside its `shouldWaitForReadiness` whitelist until logged in; RequestQrCodeAuthentication and SetAuthenticationPhoneNumber are not on it, so QR (and phone login) hung forever. QR → phone needs a fresh login (TDLib: "setAuthenticationPhoneNumber unexpected"): `restartLogin()` = LogOut → Closed → reconnect with the same creds (`restarting` flag). Credentials are saved once a QR/code is issued (restart mid-login keeps them). Login errors mapped to words (`friendly`). Auth/connection states are logged by name only (never the QR link — it's a login token). Login screen scrolls (`Centered` has verticalScroll).
- Form alignment: the phone country picker is a read-only `OutlinedTextField` (label "Country") so it matches the number field exactly; Files search = `CompactSearch` (BasicTextField + `OutlinedTextFieldDefaults.DecorationBox`, 40 dp) because OutlinedTextField's 56 dp minimum towered over the 32 dp chips.
- Login testing without the user's account: a throw-away script runs the app with `LOCALAPPDATA` = a throw-away folder; use TDLib's public example credentials (api_id 94575). Use an invalid number (e.g. +621) — never a real one (it would send an SMS). Delete the sandbox folder afterwards.
- File dialogs: `NativeDialogs` (lwjgl-nfd → modern IFileDialog, own COM thread, parent = main window). Never go back to AWT FileDialog/JFileChooser.
- Drag & drop upload (files + folders) via Compose `dragAndDropTarget`; folders recreated with `enqueueUploads`. Each folder card has its own drop target (drop on it → upload into that folder, highlighted, name in overlay); empty area → current folder. (`DragAndDropEvent.positionInRoot` is internal in Compose 1.12 — don't hit-test.)
- Media: `StreamServer` (JDK HttpServer, 127.0.0.1 + random token, Range support) → `DriveService.readRange` → TDLib partial DownloadFile. In-app player = JavaFX Media (`ui/Player.kt`, JFXPanel in SwingPanel): MP4/MOV/MP3/M4A/WAV; other formats → "Open with default app".
- Browser UX: Explorer-style selection (click / Ctrl / Shift / double-click), hover checkboxes, keys (Ctrl+A, Del, F2, Enter, Esc, Backspace), sort, Undo after trash, preview ‹ › + arrow keys, transfer badge on nav rail.

## Debugging & performance notes (2026-10-20)
- Diagnostics log: `%LOCALAPPDATA%\Donat TeleDrive\app.log` (`Log.i/e`, <2 MB, never secrets). Check it first when something "hangs".
- Hang triage: `jstack <pid>` on the java process titled "Donat TeleDrive"; look at `AWT-EventQueue-0`. A busy EDT also blocks graceful close (CloseMainWindow) — then Stop-Process is the only way.
- Fixed bug: preview rendered a JPEG as text (state race: file loaded before decode) → EDT laid out 2 MB of binary forever (60% CPU, 4.2 GB). Preview now decides `Kind` from file type up front; text capped at 256 KB in a LazyColumn; 60 s no-progress watchdog + Retry; `DriveService.cached` has a per-file Mutex and writes via `.part` + atomic move.
- Loading ≠ empty: collect Room flows with `collectAsState(null as List<X>?)` and draw nothing (or a same-size placeholder) until loaded — `emptyList()` initial values flashed "This folder is empty" on every screen switch.
- Perf rules: sample `service.live` (~300 ms) before collecting in UI; `remember` sorted lists; thumbnails go through `ThumbCache` (LRU 500). Idle CPU target ≈ 2% of one core.
- Phone width (<600dp): `PhoneShell` = Telegram-like top bar ☰ + ModalNavigationDrawer (account header) and Telegram chat-list rows (`ChatRow`) + Upload FAB. Folder path state lives in `AppModel.homePath/filesPath` so layout switches keep it.

- **Recovery net + sync robustness (2026-10-22, all unit- and live-tested):**
  - Data channel deleted → `TelegramProvider` recognises "gone" chats (`GONE` regex), forgets the cached channel; `pullLocked` sees no manifest while `remoteVersion != null` → markDirty → the PC that has the index writes it into a **new** data channel. `rebuildIndex` never wipes the local index when the backend has none (`NoManifestException`).
  - Total loss (no manifest anywhere, no PC has it): `findDrives` also finds drive channels by description `DRIVE_MARK` ("Donat TeleDrive storage." or the old "DonatTeleDrive storage.", only channels this account created); `syncDrives` → `DriveService.recover` adopts every object by name at the top level (folders/renames lived only in the index) and writes a new index.
  - Unlisted objects (`listObjects` = whole drive-channel history incl. photos/videos/audio sent from a phone, via `TelegramAccount.stored()`): Settings → "Check for unlisted files" → `findUnlisted` (refuses while uploads are pending) → `adopt` into "Recovered" (`groupObjects` joins "name.partNofM" only when complete) or `deleteUnlisted` (double-confirmed, re-checks `allRefs` right before). Adopted files have `sha256 = null` / part sha "": the first full download fills them (`fillFileSha/fillPartSha`); Verify marks VERIFIED only when there was a hash to compare.
  - Race between PCs: `saveManifestNow` loops up to `RACE_ROUNDS` = 3: after each write, `racedVersion` = a manifest newer than the one merged that this PC didn't write (`manifestVersions` newest first) → merge it (base = what we merged from) and write again. Mutation-checked: without it the other PC's rename is lost.
  - Cancelling an upload that already replaced a same-name file brings the old one back (`reparentVersions`).
  - Telegram rate-limits channel create/delete hard (FLOOD_WAIT 879 s after a few in a row); `RateLimitedException` message is human-readable.
  - Tests: `RecoveryTest` (8, FolderProvider with manifest versions + `beforeWrite` hook + `loseIndex()`); `LiveTest` = real Telegram in a temporary drive "DTD Live Test (temporary)", **app must be closed**: `gradlew jvmTest --tests donat.teledrive.LiveTest -PliveTest=true` (cleanup only: `-PliveTest=cleanup`, waits out FLOOD_WAIT).
